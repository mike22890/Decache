手机就是你的私人影音站。

Decache 是一个自托管媒体库：纯 Python 标准库后端（零第三方依赖）+ 零构建单文件前端。 装进 Android Termux 或桌面系统，一条命令起来，浏览器就是这个库。

它到底是什么

  • 一个能自己启动的本地服务：跑起来后监听 127.0.0.1:8765，浏览器打开就是完整的媒体库。
  • 一个下载队列：贴链接 → 解析 → 分 P 下载 → 自动转成 H.264 + AAC 的 MP4，全平台都能播。
  • 一个播放器：手势调进度/音量/亮度、A-B 复读、倍速、画中画、字幕、睡眠定时、WebGL 后处理特效。
  • 一份数据，放在你自己盘上：库文件是普通 JSON，媒体是普通文件，不加密、不联网校验、不绑账号。

竞品数据取自各自 GitHub 仓库（2026-11 核对）：Jellyfin 是媒体服务器、Metube 是下载器外壳、cobalt 是取流服务 —— 三者都不覆盖「下载 → 转码 → 播放 → 库管理」这条完整链路，也不以「手机本机当服务器」为目标。

装法

Android（Termux）：

# 在 Termux 里跑一次，之后只有 ~/decache 这一个目录
bash install.sh
bash ~/decache/start.sh

桌面（Windows / macOS / Linux）：解压 release 里的 take-bundle.tar.gz， Windows 双击 start.bat，其余 bash start.sh。需要 Python 3.9+（下载引擎要 3.11+）和 ffmpeg。

常见问题

要 Docker 吗？
不用。后端只依赖 Python 标准库，前端是一个 HTML 文件。整个安装过程就是解压几个文件 + 起一个 Python 进程。
能装在手机上吗？
能，这是主要用法。Android 上装在 Termux 里，服务跑在手机本机（127.0.0.1:8765），浏览器打开即用，不需要 root。
和 Jellyfin 有什么区别？
Jellyfin 管"已经有的片子"，Decache 管"从链接到能播"。Jellyfin 不做下载、不转码入库，需要 .NET 服务端；Decache 内置下载队列和转码，后端是 3100 行纯标准库 Python。
要多少内存？
常驻几十 MB 量级，因为后端是单进程标准库 HTTP 服务。转码时的内存取决于 ffmpeg 和分辨率。
会收集数据吗？
不会。没有账号体系、没有遥测、没有云端。库文件和媒体都在你自己的磁盘上，服务默认只监听本机回环地址。
支持哪些站点？
取决于你装的下载引擎（yt-dlp / ytta / you-get）。本项目刻意不内置任何站点的解析代码 —— 引擎支持什么就支持什么，站点改版由引擎升级解决。
为什么后端只有 3100 行？
因为不引依赖。HTTP 服务、JSON 存储、Range 请求、HLS 直出、封面抽帧全部用标准库 + 一个 ffmpeg 子进程解决，没有框架层。
